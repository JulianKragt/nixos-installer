**4.2 — Recovery (CLI, not a stage).** Runs on the provider.

Purpose: one tool for the first install, for resuming after a failure, and for later user changes.

Expects: all stages exist.

Must do: subcommands in `cmd/nixos-installer/flags.go` — `install` (default; resumes from `State.Completed`), `secrets` (re-runs 1.1 through 4.1 on an installed host even when they are in `State.Completed`; this is the add/remove-a-user path in CONTEXT "Users"), `status` (prints the state file and the phase derived from `Completed`: installing, awaiting the secrets phase, converged; see ROADMAP "Plumbing design"); a `--from <id>` flag; `install --reinstall`.
- Decide how the re-run is expressed. CONTEXT §7 suggests filtering `stages.All`, but `pipeline.Run` skips completed stages (`pipeline.go`), so filtering alone does not re-run 1.1–4.1. Expect run options passed to `pipeline.Run` (from / only / force), a way to mark the "secrets" group, and no duplicate IDs in `State.Completed` when a stage runs twice (`runStage` appends unconditionally today). There is no `Marker`: `Completed` alone records progress, so a forced re-run removes the IDs it is about to run from `Completed` and saves before running anything. Otherwise a failed `secrets` run would still show 3.3 as done.
- `--reinstall` (typed confirmation, archives the old state file, starts fresh): after a full install `Completed` lists every stage, so a second run does nothing, but ROADMAP §6.6 and the final acceptance test need 0.1–1.1 to run again with the new host key.
- Stage 0.0 must be phase-aware (0.1 does this; check it): no root-password bootstrap once 0.2 is complete, no disk questions in `secrets` or `status`.
- Cover `secrets` on a provider that has no state file or pinned host key for the host (the key must be confirmed by fingerprint). `status` needs only `--host`; `resolveInputs` asks for the target and config unconditionally today.
