**Stage 0.2 — Base install.** Runs on the provider, acting on the target.

Purpose: install the `<host>-bootstrap` configuration with nixos-anywhere, then wait for the installed system and pin its SSH host key.

Expects: stage 0.1 (`install.json` written, passphrase on the target, `PrimaryUser` in State).

Must do:
- Re-check `/tmp/disko-password`; ask again if it is gone.
- Skip nixos-anywhere when the target already runs the installed bootstrap system (hostname equals the host and it is not the ISO). The legacy `test -f /run/current-system` check never worked.
- Run `nix run github:nix-community/nixos-anywhere/<pinned ref> -- [--generate-hardware-config nixos-generate-config <path>] --build-on-remote --flake <ConfigDir>#<host>-bootstrap --target-host root@<ip>`, output streamed to the runner. New flag `--generate-hardware` (default true).
- Commit `hardware-configuration.nix` and `install.json` in config, listed paths only, only if changed.
- Wait for SSH: poll every 5 s up to a new `--ssh-wait-timeout`, tell the operator to type the LUKS passphrase at the console, accept only a host key that differs from the ISO's, show its fingerprint.

Introduces shared plumbing (design in ROADMAP "Plumbing design"):
- Host key pinning. It replaces both `StrictHostKeyChecking=no` in `pipeline.SSH` (`machine.go`) and `ssh.InsecureIgnoreHostKey()` in `BootstrapKey` (`bootstrap.go`); both carry a TODO (see CONTEXT §7 "Host key"). Pins are keyed by host name (`HostKeyAlias=<host>`) in a per-host known_hosts file under the state dir, not by IP: the target IP is a per-run input and can change between the ISO and the installed system. The ISO's key is pinned at first contact in 0.0, with its fingerprint shown, so a swapped target is noticed before the LUKS passphrase is sent. After first boot the installed system's key replaces it (TOFU) and every later connection checks against it. nixos-anywhere kexecs into another system with its own host key; decide in your plan which ssh options it gets.
- `Machine.SSHArgs()`, so nixos-anywhere (and anything else that spawns ssh) uses the same ssh configuration as `Machine`.
- `pipeline.NewEnv(inputs, state)`, which builds Local and Remote from the inputs and the State (pinned or not), and `Inputs.StateDir` with the planned `--state-dir` flag. Today `main.go` builds `Remote` from the IP alone and the state dir never reaches `Env`.
- No `ControlMaster` by default. OpenSSH applies the master's `ForwardAgent` to the sessions multiplexed over it (verify), which conflicts with the opt-in agent forwarding of 2.0. If it is used after all (measured slow), put the forwarding mode in `ControlPath` and keep the path short: macOS limits socket paths to 104 bytes.

Writes State: `HostKeyFingerprint`.
