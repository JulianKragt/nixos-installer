**Stage 0.2 — Base install.** Runs on the provider, acting on the target.

Purpose: install the `<host>-bootstrap` configuration with nixos-anywhere, then wait for the installed system and pin its SSH host key.

Expects: stage 0.1 (`install.json` written, passphrase on the target, `PrimaryUser` / `Users` in State).

Must do:
- Re-check `/tmp/disko-password`; ask again if it is gone.
- Skip nixos-anywhere when the target already runs the installed bootstrap system (hostname equals the host and it is not the ISO). The legacy `test -f /run/current-system` check never worked.
- Run `nix run github:nix-community/nixos-anywhere/<pinned ref> -- [--generate-hardware-config nixos-generate-config <path>] --build-on-remote --flake <ConfigDir>#<host>-bootstrap --target-host root@<ip>`, output streamed to the runner. New flag `--generate-hardware` (default true).
- Commit `hardware-configuration.nix` and `install.json` in config, listed paths only, only if changed.
- Wait for SSH: poll every 5 s up to a new `--ssh-wait-timeout`, tell the operator to type the LUKS passphrase at the console, accept only a host key that differs from the ISO's, show its fingerprint.

Introduces shared plumbing: host key pinning in `pipeline.SSH` (the TODO in `internal/pipeline/machine.go`, see CONTEXT §7 "Host key"). Before the install the ISO's key is accepted as today; after first boot the key is stored (TOFU) in a known_hosts file under the state dir and every later connection checks against it. nixos-anywhere, and later nixos-rebuild, get the same ssh options so there is one SSH configuration. Consider `ControlMaster` so each command does not open a new connection.

Writes State: `HostKeyFingerprint`.

Legacy reference: Phase 3–4, lines 381–438, and `pin_target_host_key` at 191–202.

Done when: the known_hosts handling and the "is this the installed system" decision have tests; a wiped test target boots the bootstrap system; a second run skips the stage; a changed host key is refused.
